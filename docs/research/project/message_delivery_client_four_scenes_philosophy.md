# 消息折纸

“消息折纸”把一次聊天链路视为被折叠过的纸面：同一张纸上同时存在本地预期、网络往返、服务端确认和会话列表回声。画面不追求写实，而用清晰的折线、箭头和分层色块表达状态如何从用户手指流入系统，再回到界面。最终作品应当像被反复校准过的技术插画，边距、节点、节奏都带着细致打磨后的稳定感。

空间以四格漫画为骨架，每一格只讲一个前端必须处理的场景。角色、设备、服务端、数据库和 WebSocket 不是装饰，而是信息节点；它们之间的距离代表同步成本，箭头的粗细代表用户感知强弱。每一格都需要显得经过长期推敲，像资深信息设计师用无数次微调换来的结果。

颜色承担状态语义：蓝色代表客户端动作，绿色代表确认与成功，橙色代表等待与 pending，红色只用于未读和需要注意的状态。文字保持克制，只留下动作名、帧名、状态名和少量提示语，避免把漫画变成说明书。画面本身必须先能讲清楚故事，文字只是锚点。

构图强调“先上屏，再确认，再同步”的节奏。发送场景要有明确的乐观上屏瞬间；接收场景要突出 WebSocket 推来的新消息如何被当前会话消费；会话列表场景则像余波一样更新 preview、time 和 unread。每个元素都应当有专业插画级别的收口，线条、圆角、阴影和留白都不能粗糙。

这套视觉语言要兼具漫画的亲和力和工程图的可信度。它不是儿童式涂鸦，而是一张可以放进项目调研目录的精致图解：轻松可读，边界准确，信息层次严谨，能让熟悉 IM 链路的人一眼看出当前版本的客户端责任范围。
